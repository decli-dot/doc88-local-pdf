# RuCaptcha — локальный эксперимент

В dev-режиме (Ctrl+Shift+D) доступен блок **RuCaptcha · подтверждение доступа**.
В нём можно сохранить или удалить ключ, включить автоматическое решение, бесплатно проверить баланс и при необходимости задать число попыток. Ноль в панели означает отсутствие ограничения.

Поддерживается наблюдавшаяся на Anna’s Archive **текстовая капча DDoS-Guard**:

1. Программа ожидает обычную проверку браузера и открывает виджет.
2. В RuCaptcha передаётся только изображение с символами; маленькое изображение увеличивается для читаемости. Ответ запрашивается с интервалом не менее пяти секунд.
3. Полученный текст вводится в тот же виджет. Изменившееся изображение не получает устаревший ответ.
4. Продолжение подтверждается реальной загрузкой страницы источника. Ответ API сам по себе не означает, что доступ открыт.
5. Если сайт отклонил текст или после отправки показал новую картинку, программа распознаёт новую проверку и повторяет попытку. Устаревший ответ не вводится в изменившуюся картинку. Если настроен лимит отправок, он сохраняется.
6. При временном сбое `getTaskResult` повторно запрашивается результат того же `taskId`: новая платная задача не создаётся. Опрос идёт с паузой не менее пяти секунд; после четырёх последовательных ошибок либо общего тайм-аута сохраняется понятный код ошибки и ручное подтверждение.

Смена заголовка страницы не считается подтверждением доступа, пока видна проверка. Ожидаемые переходы и исчезновение iframe после отправки не превращаются в ошибку. Диагностика различает этапы получения изображения, ожидания сервиса, отправки и проверки страницы; числовой код браузера `23` заменён кодом соответствующего тайм-аута.

Обработчик различает два наблюдавшихся варианта **капчи Doc88**: прежний пазл с прорезью и проверку с несколькими контурами фигур (`read-shape-board`, наблюдается с `reader_shape=1`). Для пазла RuCaptcha указывает центр прорези; для фигур — центр контура, совпадающего по форме, размеру и ориентации с заполненной подвижной фигурой слева. Инструкция отправляется вместе с увеличенной областью картинки в `CoordinatesTask`; чужие контуры не считаются целью. Если картинка уже видна, предварительное нажатие на ползунок не выполняется. Скрытый пазл сначала открывается коротким нажатием.

Положение движущегося фрагмента программа берёт из геометрии виджета. После ответа она проверяет границы, неизменность картинки, варианта виджета и адреса страницы, начинает отдельное перетаскивание и ожидает появления первой страницы документа. В диагностике сохраняется вариант `shapes` или `puzzle`. Во время ожидания сервиса мышь не удерживается; при отмене перетаскивания кнопка отпускается. Значения проверки и защитные cookies не подменяются.

**Статус нового варианта на 24 ноября 2026:** автоматическое прохождение на живом Doc88 не подтверждено. В двух проверках ASME Y14.1-2020 отправлено семь задач: шесть ответов не привели к открытию документа, одна задача завершилась `ERROR_CAPTCHA_UNSOLVABLE`. Новый виджет также собирает данные взаимодействия с браузером; точная причина отклонения ответов не установлена. Прохождение тестов на макетах означает корректную обработку состояний, но не принятие ответа реальным сайтом. Ручная панель сохраняется.

Решатель подключён к обычному браузерному загрузчику Doc88, включая автоматическое переключение с прямого извлечения на OCR. Строгий режим прямого извлечения сам не открывает интерактивные проверки; неизвестные виджеты сохраняют ручное подтверждение. Проверки языка, издания и полноты документа не меняются.

## «100% распознавание»

Этот режим включается пользователем в кабинете RuCaptcha. Программа не создаёт собственные дополнительные копии задач для повторного голосования: это умножило бы оплату поверх настройки аккаунта. Время ожидания ответа увеличено до пяти минут. Название режима не является гарантией принятия ответа сайтом. Лимиты программы считают **отправленные задачи**, а не число оплачиваемых работников внутри одной задачи; стоимость берётся из ответа сервиса.

## Хранение и оплата

- Ключ хранится в `.data/captcha-settings.json`; `.data/` исключён из Git и сборок релиза. В ответах сервера, HTML, localStorage, заданиях и диагностике ключ отсутствует. API возвращает только признак его наличия.
- Настройки доступны только после входа в dev-режим. Сам решатель, если включён, работает и при поиске в обычном окне.
- По умолчанию функция выключена. По умолчанию лимитов на задание и сутки нет (`null`). По запросу пользователя ограничения в текущих локальных настройках также сняты. Продолжение того же задания сохраняет его лимит.
- Счётчик `.data/captcha-usage.json` записывается **до** отправки платной задачи. Неопределённый сетевой результат тоже занимает попытку; платный запрос автоматически не повторяется. Отмена прекращает ожидание, но уже отправленная задача может тарифицироваться поставщиком.
- Временные сбои получения результата не расходуют новые отправки; число таких повторов хранится в `pollRetries`. Отправка `createTask` после неопределённой сетевой ошибки не повторяется автоматически.
- Распознанные ответы, картинки и ключ не записываются в счётчик. Хранятся идентификатор задачи сервиса, статус и стоимость, сообщённая сервисом. Проверка баланса не создаёт платных задач.
- Отключение решателя прекращает новые отправки; текущая отправленная задача может завершиться. Новые установки не получают чужой ключ.

## Проверка

Локальные тесты проверяют сохранение и удаление ключа, закрытые настройки, отсутствие ключа в API, ограничения при одновременных запросах, сохранение лимитов после перезапуска, отмену, неподдерживаемые проверки и ввод именно ответа сервиса на тестовой странице. Интерфейс проверяется на русском и английском, в том числе на узком экране.

Реальный результат проверки источника описывается отдельно в локальном отчёте `.data/captcha-review/RESULTS.md`; успешные тесты на макетах не заменяют проверку на сайте.
