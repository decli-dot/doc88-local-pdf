# Прямое получение PDF — эксперимент

Модуль подключён к локальному поиску DecliPDF. По умолчанию выбран автоматический способ: программа пробует прямое извлечение, при необходимости распознаёт отдельные страницы и при технической неудаче использует прежнюю обработку изображений.

Ручной выбор находится в dev-режиме (`Ctrl+Shift+D`): **Автоматически**, **Прямое извлечение**, **Изображения + OCR**. В обычном интерфейсе новые задания всегда используют автоматический режим. ZIP обрабатывается через OCR. Выбранный способ сохраняется в задании и наследуется документами очереди.

## Что делает

1. Уточняет обозначение DIN по каталогу и находит подходящую страницу документа.
2. Получает список ресурсов из HTML, который сайт отдаёт своему просмотрщику.
3. Загружает ресурсы в ограниченном пуле, собирает и проверяет каждую страницу.
4. Преобразует страницы в PDF в трёх отдельных процессах конвертера.
5. Проверяет текст, язык, обозначение, год и объём; формирует структуру и текстовый файл.

Если текст уже пригоден для поиска, OCR не запускается. Страницы со сканами и обложки с неполным текстовым слоем могут распознаваться отдельно; остальные страницы сохраняют исходную графику. Пустой лист или векторный чертёж с небольшим количеством текста сами по себе не требуют повторного распознавания всего документа.

При неподходящем языке, другом издании или подтверждённой неполноте вариант отклоняется. Автоматическое переключение не используется для обхода этих проверок. При отсутствии Java или ошибке преобразования автоматический режим возвращается к обработке изображений. Принудительный режим прямого извлечения сообщает об ошибке.

## Запуск

Для прямого извлечения нужны зависимости проекта и Java 17 или новее. На этой машине проверено с Java 21. Конвертер FFDec 26.4.0 загружается отдельно при первом запуске; архив проверяется по закреплённому SHA-256. Он хранится только в `.data/direct-experiment/tools`. Без Java доступен прежний способ OCR.

Ниже приведены команды отдельного диагностического сценария DIN. Основной интерфейс поддерживает все подключённые издательства.

```powershell
npm run experiment:direct -- --query "DIN 129-1"
```

Для сравнения именно обработки одного файла можно указать страницу источника и сохранённую запись каталога:

```powershell
npm run experiment:direct -- --query "DIN 129-1" --url "https://www.doc88.com/p-18168430502793.html" --edition ".data/direct-experiment/din129-edition.json"
```

Дополнительные параметры:

| Параметр              | Значение                                                 |
| --------------------- | -------------------------------------------------------- |
| `--workers 4`         | Одновременные загрузки, от 1 до 16                       |
| `--convert-workers 3` | Процессы конвертации, от 1 до 4                          |
| `--directory <папка>` | Папка внутри `.data/direct-experiment`                   |
| `--download-only`     | Только получить и проверить ресурсы страниц              |
| `--convert-only`      | Повторить конвертацию уже полученных ресурсов            |
| `--inspect-only`      | Повторить проверку готового `source.pdf`                 |
| `--resolve-only`      | Только уточнить обозначение по каталогу и найти источник |

Для последних двух параметров укажи `--directory` предыдущего запуска. Для чистого замера используй новую папку. Существующие задания приложения не изменяются.

## Результаты

Путь запуска выводится в консоль. В нём находятся:

- `result.pdf` — документ, прошедший обязательные проверки;
- `text.txt` — извлечённый текст;
- `report.json` — время этапов, число страниц и контрольные суммы ресурсов;
- `quality.json` — язык, издание, объём, нумерация и структура;
- `samples/` — изображения выбранных страниц для визуальной проверки;
- `source.pdf`, `swf/`, `export/` — промежуточные данные.

Время поиска по каталогу и подготовки конвертера не входит в замер обработки. Сетевые задержки учитываются, поэтому сравнивать следует несколько запусков. Проверка счётчика страниц подтверждает объём, заявленный источником; проверка нумерации отдельно может остаться неуверенной, что видно в `quality.json`.

## Границы эксперимента

- Диагностический сценарий `experiment:direct` ориентирован на DIN. Локальный поиск проверен также на ISO и ASME.
- Доступны только страницы из списка, переданного обычному просмотрщику. Скрытые страницы не сканируются.
- CAPTCHA автоматически не решается. При недоступных данных просмотрщика модуль останавливается с сообщением о ручном подтверждении доступа.
- Единичные сетевые ошибки повторяются не более двух раз. Для отказа HTTP не подбираются другие хосты или прокси.
- Проверен случай, когда пустой символ в шрифте ошибочно закодирован как табуляция: замена на пробел выполняется только при совпадении контура с настоящим пробельным символом в том же словаре. Положение и геометрия остальных знаков сохраняются.
- Все документы, профили браузера и инструменты остаются в игнорируемой папке `.data`.

Транспорт, сборка страниц, организация обработки и проверки написаны в этом проекте. Для преобразования SWF используется отдельное приложение [JPEXS FFDec](https://github.com/jindrapetrik/jpexs-decompiler), лицензия GPL-3.0. Исходный код `doc88_extractor` в модуль не включён.
