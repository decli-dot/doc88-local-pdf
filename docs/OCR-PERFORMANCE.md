# Ускорение OCR и размер PDF

Проверка локальной версии от 8 ноября 2026 года. Один и тот же набор из **154 страниц ISO 1101:2017**, без готовых результатов OCR в обоих запусках.

| Показатель                                    |         До |      После |
| --------------------------------------------- | ---------: | ---------: |
| Распознавание и сборка из сохранённого архива | 6 мин 31 с | 2 мин 27 с |
| Размер PDF                                    |   400,0 МБ |   321,1 МБ |
| Страниц                                       |        154 |        154 |
| Пунктов структуры                             |        151 |        151 |

На этом компьютере обработка ускорилась примерно **в 2,7 раза**, файл уменьшился примерно **на 20%**. Размеры указаны в десятичных мегабайтах. Это сравнение обработки уже скачанных страниц: время каталога и загрузки документа сюда не входит. Использовались Windows, 16 логических процессоров, около 31 ГиБ оперативной памяти и установленный Tesseract с английской моделью.

## Как работает

Страницы распознаются независимо, итоговый PDF собирается в исходном порядке. Число одновременных задач подбирается по доступным процессорам и свободной памяти: до четырёх для установленного Tesseract, до двух для встроенного движка. Небольшие задания по умолчанию обрабатываются одним процессом. Модели встроенного движка загружаются последовательно, затем используются независимыми обработчиками.

Для каждого внешнего процесса установлен один поток OpenMP, чтобы параллельные страницы не создавали лишние потоки внутри OCR. Такой способ обработки нескольких изображений соответствует [рекомендациям Tesseract](https://tesseract-ocr.github.io/tessdoc/FAQ).

Готовая страница записывается в кэш вместе с текстом и контрольными суммами; запись метаданных выполняется последней. При отмене или ошибке новые страницы не запускаются, программа дожидается остановки уже запущенных задач. Продолжение использует только полностью записанные и проверенные результаты. Старые совместимые постраничные кэши проходят сжатие без повторного OCR.

Изображения сжимаются **без потерь**: сохраняются размеры, пиксели и цвета. Используется PNG-предсказание в PDF, а серые изображения при совпадающих RGB-компонентах могут храниться одним каналом. Перед заменой программа декодирует результат и проверяет равенство пикселей. JPEG, необычные цветовые пространства и неподдерживаемые потоки не преобразуются. Если сжатие не уменьшает поток или недоступно, остаётся исходное изображение.

## Проверка качества

- Текст всех 154 страниц совпал побайтно с результатом прежнего OCR. Показатели уверенности распознавания и структура документа также совпали.
- Независимым чтением проверены исходные пиксели страниц 1, 10 и 56; отдельно сравнены изображения этих страниц после отображения в Poppler. Различий нет. Проверка включает обложку, текст с цветными ссылками и страницу с чертежом и мелкой таблицей.
- Полный поиск по сохранённым страницам заново прошёл проверки английского языка, письменности, издания и полного объёма. Меньший PDF сохранён в общем кэше; повторный запрос через каталог занял около пяти секунд.
- Проверены отмена и продолжение параллельного OCR, остановка встроенных обработчиков во время загрузки моделей, порядок страниц и обработка повреждённых кэшей.
- Пройдены **140 автоматических тестов**, проверка синтаксиса, сборка браузерной версии и проверка интерфейса RU/EN на широком и узком экранах. Ускорение относится к локальной программе.

<details>
<summary>Повторение замера для разработчика</summary>

`node scripts/validate-ocr-speed.cjs --label ИМЯ --workers 4 --archive ПУТЬ` создаёт отдельный пробный каталог в `.data/ocr-speed-review`. Для свежего замера требуется новое имя из латинских букв, цифр и дефисов. `--resume` продолжает существующий каталог. Каталог обычных заданий не меняется.

Исходный замер `baseline` выполнен прежним последовательным кодом. Запуск новой версии с `--workers 1` сравнивает настройки уже нового движка, а не восстанавливает старую реализацию. Подробные результаты сохранены в `.data/ocr-speed-review/comparison.json`.

Переменная окружения `DECLIPDF_OCR_WORKERS` задаёт желаемый предел от 1 до 4; ограничения по памяти, процессору и типу движка остаются действующими. Обычный интерфейс выбирает настройки автоматически. Поля `ocrDiagnostics` и `pdfOptimization` доступны в диагностике и не показываются обычным пользователям.
